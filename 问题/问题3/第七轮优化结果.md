# 第七轮第三问优化结果：未达到发布门槛

> 此报告是早期“第七轮”候选，未发布；它不同于随后引入队内方案、最终采用的[round7](round7学习融合与发布验证.md)。文中“当前”指当时。

本轮完成32个候选变体的离线研究。最好的冻结组合在全新108个案例中，从250.25降到244.99秒/源，平均提速2.10%，低于开发前设定的3%采用门槛。没有切换运行入口，也不建议为本轮候选新开三次演练。第四问保持原策略，正式测试和新演练次数均为0。

当前命令仍运行round6基线；它只是保留的可运行版本，不代表用户已认可其为最终方案。用户刚完成的三次演练全部保留为历史证据，已标记为“未选作最终策略，继续优化”。本报告是算法研究结果，未更新旧论文PDF及支撑包。

## 1. 研究范围与验证纪律

第一阶段包含26个候选与round6基线：规则环站数、非对称布局、全部扫描任务联合排序、探索优先权重、清除点进出路径、外环反馈旋转、首个外站锚点复用、放宽停点补测、测向质量代理、面积质心代表位置，以及部分组合。追加阶段比较6个有预算未知频道补扫候选。

开发案例为150012—150083，共72个独立场景；大部分方案先跑前36个，通过初筛的组合扩展至72个。第一阶段在完整72例候选中选平均秒/源最小者。不同测试样本量的方案不能直接按各自均值排成总榜。

第一阶段开发共1116次唯一“策略×案例”运行；追加阶段432次。冻结后使用180000—180107这108个新场景，基线和候选配对运行216次；另有70个边界压力场景。合计1834次离线基准运行全部清除，覆盖及逐步位置包含审计通过。**1834是运行次数，不是1834个独立随机样本。** 54项关键测试通过。

第一阶段未通过门槛后，180053的退步用于追加机制诊断，因此原108例不再作为追加方案的独立验证。追加方案均未通过开发筛选，预留的198000—198107没有使用，也没有据此产生新的独立验证结论。

预先记录与代码冻结见第一阶段决策（原始资料未纳入本公开版）、追加决策（原始资料未纳入本公开版）、策略冻结（原始资料未纳入本公开版）。

## 2. 哪些方向没有达到预期

下表为同一批前36个开发案例。基线均值249.06秒/源；数值越小越好。仅用于解释筛选，不是最终留出成绩。

| 候选 | 秒/源 | 发现 |
|---|---:|---|
| 中心＋7个外站，共8站 | 254.22 | 环更小，但增加检测和定位绕行，整体更慢 |
| 中心＋8个外站，共9站 | 253.50 | 同样未胜出 |
| 中心＋9个外站，共10站 | 251.81 | 仍未胜出 |
| 中心＋10个外站，共11站 | 254.33 | 不能用纯覆盖路线短代替总时间短 |
| 非对称7站 | 248.61 | 几何路径优化只带来很小实际收益 |
| 全部剩余扫描站参与评分 | 248.45 | 有小幅收益，许多动作仍不变 |
| 清除点兼顾入站、出站 | 248.74 | 单个清除点可优化空间本来就有限 |
| 外环朝向按反馈旋转 | 248.79 | 布局朝向不是本批的主要瓶颈 |
| 锚点替代首个外站 | 250.30 | 有成功替代，但全任务平均反而慢 |
| 测向质量代理，β=1/2/4 | 252.06 / 253.01 / 263.89 | 为缩小定位域走更多路，不划算 |
| 用面积质心作路线代表点 | 251.98 | 换代表位置不能稳定改善路线 |

非对称布局搜索采用题设几何约束下的多初值数值优化，最终用连续覆盖距离及独立四叉树验证；不以采样点覆盖替代连续证明，不声称获得全局最短路径。几何搜索目标与完整任务目标的差异，正是本轮的一个主要负结果。

## 3. 冻结组合与新留出结果

第一阶段所选组合为：所有扫描站参与剩余中心路线评分；扫描服务费在调度代理中权重0.25；适度放宽有上限的停点补测；保证清除点同时考虑去往下一目标的距离。实际移动、检测、切频和清除费用按题设全额计算，0.25不是费用折扣。

| 指标 | round6基线 | 冻结候选 |
|---|---:|---:|
| 平均秒/源 | 250.25 | 244.99 |
| P90秒/源 | 337.87 | 332.65 |
| 最慢案例秒/源 | 399.99 | 400.54 |
| 清除数（108例总计） | 1404 | 1404 |
| 检测次数 | 11143 | 11768 |
| 失败清除次数 | 425 | 459 |

108例中79例更快、29例更慢。平均节省5.26秒/源，配对bootstrap 95%区间为[2.74,7.63]秒/源；这是合成场景机制下的统计证据，不是官方成绩预测。最坏退步发生在180053，每源增加73.42秒。平均收益为正，不代表每种误差模式或每个案例受益。

费用分解按“每个案例的平均费用”统计：移动时间少101.67秒，检测多28.94秒，切频多6.40秒，清除多0.94秒，净节省约65.39秒/案例。因此确实减少了移动，但额外信息获取费用抵消了相当一部分收益。

按实际源数事后分组：10源提速2.62%，13源提速1.03%，16源提速2.67%；均匀位置分组提速3.45%，边界分组仅0.91%，平滑误差分组反而慢0.48%。这些分组只供诊断，不能把评估器知道的真实源数、位置模式或误差模式交给策略，让它事后挑赢家。

采用门槛要求平均提速至少3%，本候选未通过。证据完整保存在新留出审查（原始资料未纳入本公开版），不更改门槛来包装成通过。

## 4. 接近16源时补扫的追加结果

追加方案在当前位置只扫描未知频道，按已发现源数触发，最多1或2轮，每次与过去完整扫描位置至少相距250米。达到16个已发现源才按题给上限取消搜索；14或15个源时仍须完成剩余频道的覆盖证明。

完整72例开发集上，第一阶段组合为243.82秒/源。追加结果如下。

| 触发已发现数 | 最多补扫轮数 | 秒/源 |
|---|---:|---:|
| ≥10 | 1 | 246.44 |
| ≥10 | 2 | 249.44 |
| ≥12 | 1 | 245.23 |
| ≥12 | 2 | 246.52 |
| ≥14 | 1 | 244.29 |
| ≥14 | 2 | 244.50 |

六种追加方案均未超过原组合，全部在开发阶段淘汰，没有继续消耗新留出或用户演练。补扫可能帮助特定案例提前达到16源，也可能只给不存在的频道增加费用；该机制不能无条件使用。14、15源仍需证明剩余频道不存在，以及16源可停止搜索，均有独立关键测试。
