# 四问最终代码策略

这里将最终方案的代码按题目分类，供阅读和程序调用。代码来自 `论文/支撑材料.zip` 中的最终代码，而非汇集各轮实验；为配合本目录，`公共代码/current_policy.py` 的配置路径改为 `配置/当前策略.json`，其余复制的 Python 源码未改。原来的 `src/`、`tests/`、论文和参考资料保持原样。

| 位置 | 内容 |
|---|---|
| `问题一/geometry.py` | 测向可行域、最小包围圆及可靠清除等几何函数，也被其他问题复用。 |
| `问题二/` | 第二次观测点设计和连续选址数值核验。 |
| `问题三/` | CCR-JS：最终第三问策略、适配器、队友方案的7个底层文件及覆盖核验。 |
| `问题四/` | VC-SVS：最终第四问策略、定向覆盖核验与相关调度模块。 |
| `公共代码/` | 各问共用的动作费用、求解接口、几何覆盖、光学后备等依赖。 |
| `配置/当前策略.json` | 固定第三问为 CCR-JS、第四问为 VC-SVS 的 `no_probe`，正式测试入口保持关闭。 |
| `入口.py` | 添加本目录内各模块路径，提供 `configuration` 和 `make_robot`；导入本文件不会自行连接模拟器。 |

阅读建议：第一、二问从各自的 `.py` 开始；第三、四问分别先看 `q3_ccr_js.py`、`q4_vc_svs.py`，再顺着导入查看依赖。`q4_vc_svs.py` 中保留支撑包源码里的其他研究变体，最终使用的具体变体由配置固定为 `no_probe`；不要把同文件中的所有分支都当成最终选择。

在本文件夹内的 Python 会话中，可以通过 `import 入口` 加载模块；`入口.make_robot(backend, 3)` 和 `入口.make_robot(backend, 4)` 分别构造最终策略，其中 `backend` 必须由调用方提供符合项目接口的对象。直接导入不会启动测试，构造对象也不是完整演练。第一、二问的函数可在导入 `入口` 后从 `geometry` 和 `q2_design` 等模块导入。

依赖见 `requirements.txt`。本目录是为阅读和复用重新整理的副本，不能与工作区 `src/` 的入口、配置或底层文件随意混搭。正式测试已经完成，不应再次启动。整理版与支撑包采用同一份核心源，有限离线检查不等于所有场景完全等价或在新电脑上已经复现。
